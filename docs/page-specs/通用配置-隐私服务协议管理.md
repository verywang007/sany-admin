- 当前值对应项加 selected 样式；点击项写入值并关闭。
- 再次点击同一控件关闭；点击页面其他位置关闭；打开下拉会关闭日历，反之亦然。
- 清除按钮（×）：值置为空串（显示为空，而非「全部」）。

日期区间行为：
- 双月面板并排：左面板头部有 `«`（上一年）`‹`（上一月），右面板头部有 `»`（下一年）`›`（下一月）；月份标题 `YYYY年 M月`；星期头 `日 一 二 三 四 五 六`；每面板 6 行 × 7 列，非本月日期灰显（old/new），今天高亮（today）。
- 第一次点击设开始日（结束清空），第二次点击设结束日；若第二次早于开始日则自动交换；选完第二个日期后自动关闭。区间内日期 in-range 样式，端点 selected。
- 初始视图月份 = 已选开始日所在月，否则当前月。
- 面板底部 footer 左对齐一个 `清除` 链接：清空并关闭。控件右侧清除按钮同样清空。

## 4. 表格

c7n-pro Table，带边框（bordered），行高固定 36px（0.36rem，表头 inner line-height 0.34rem），表头列可拖拽（resizer），表格 `width:100%; min-width:14.4rem(1440px)`，外层 `margin-top:8px`。无复选框列、无序号列、**无固定列**，无排序，无行点击。

### 4.1 列定义

> 注意：HTML `<colgroup>` 只写了 8 个 `<col>`（1rem / 1.5rem / 1.4rem / 1.4rem / 0.9rem / 1rem / 0.8rem / 2.4rem），而表头有 9 列，按顺序对位后「状态」被分到 140px、「发布人」240px、「操作」无宽度，明显是少写了一个 col。下表「建议宽度」采用方案文档的宽度（与 colgroup 的值集合一致，只是补上了状态列 90px），「HTML 实际对位」列如实记录。

| # | 列标题 | dataIndex | 建议宽度 | HTML 实际对位 | 对齐 | 渲染 |
|---|---|---|---|---|---|---|
| 1 | 发布编号 | `version` | 100 | 100 | 左 | 链接样式（`#29bece`，`font-weight:600`，hover 下划线），点击 = 「查看」 |
| 2 | 适用站点 | `site` | 150 | 150 | 左 | 单站点：站点名；多站点：首个站点 + `等N个`（`#29bece`，12px，margin-left 2px，原生 `title` = 全部站点用 `、` 连接） |
| 3 | 状态 | `status` | 90 | 140 | 左 | 圆点 + 文字（见 4.2） |
| 4 | 生效时间 | `effectiveTime` | 140 | 140 | 左 | `eff`，空显示 `-` |
| 5 | 失效时间 | `expireTime` | 140 | 90 | 左 | `exp`，空显示 `-` |
| 6 | 触达人数 | `totalUser` | 90 | 100 | **右**（`font-variant-numeric: tabular-nums`） | `total.toLocaleString('en-US')`（千分位），0 显示 `-` |
| 7 | 同意人数 | `agreeUser` | 100 | 80 | **右**（tabular-nums） | 非 0：千分位数字，链接样式（同发布编号），点击见 §7.8；0 显示 `-`（非链接） |
| 8 | 发布人 | `publisher` | 80 | 240 | 左 | 文本 |
| 9 | 操作 | `action` | 240 | 未设置 | 左 | 文字按钮组，按状态渲染（见 4.3） |

### 4.2 状态渲染（`.local-st`）

圆点 6×6、圆角 50%、右边距 5px；文字 12px、行高 20px、不换行；文字颜色继承（#333 系），只有圆点着色：

| 编码 | 文案 | class | 圆点色 |
|---|---|---|---|
| `DRAFT` | 草稿 | `is-draft` | `#bfbfbf` |
| `SCHEDULED` | 待生效 | `is-sched` | `#29bece` |
| `PUBLISHED` | 已发布 | `is-pub` | `#52c41a` |
| `EXPIRED` | 已失效 | `is-exp` | `#8c8c8c` |

状态元数据另有 `canEdit`（仅 DRAFT 为 true）与 `canDelete`（仅 DRAFT 为 true），脚本中未直接使用。

### 4.3 操作列

文字按钮（`.local-op`）：`#29bece`，12px，无背景无边框，`margin-right:10px`，hover `#1995a8` + 下划线；危险按钮 `is-danger` `#d50000`，hover `#b00000`；（另定义了 `is-disabled`：`rgba(0,0,0,.25)`、not-allowed，未使用）。容器 flex、不换行。

| 状态 | 操作（从左到右） | data-act |
|---|---|---|
| 草稿 DRAFT | `编辑`、`发布`、`删除`(红) | edit / publish / delete |
| 待生效 SCHEDULED | `查看`、`取消发布` | view / cancel |
| 已发布 PUBLISHED | `查看`、`基于此版本新建` | view / copy |
| 已失效 EXPIRED | `查看`、`基于此版本新建` | view / copy |

不可用的操作**不渲染**（不是置灰）。

### 4.4 分页

c7n-pro Pagination，表格下方 `margin-top:10px`：
- `每页行数：` + 小号下拉，选项 `10 / 20 / 50 / 100`，默认 `20`（可选，但不影响数据）。
- 页码信息 `#local-page-info`：`1 - {n} / {n}`，每次渲染按 ROWS 长度刷新；初始 `1 - 6 / 6`。
- 首页 / 上一页 / 下一页 / 末页 4 个图标按钮，全部 disabled。
- 实际不分页（所有行一次渲染）。

## 7. 交互逻辑

### 7.1 状态机（实现）

```
新建版本 ──► DRAFT(草稿)
DRAFT ──[列表「发布」 / 编辑视图「提交发布」(校验通过)]──► SCHEDULED(待生效)
SCHEDULED ──[取消发布(原因≥5字)]──► DRAFT
DRAFT ──[删除]──► (移除)
PUBLISHED / EXPIRED ──[基于此版本新建]──► 打开 copy 模式编辑视图（不新增行）
```

- 原型中没有 `SCHEDULED → PUBLISHED`（到点生效）和 `PUBLISHED → EXPIRED`（被取代）的流转，这两个状态只来自 mock 数据。
- 「立即生效」也进入 `SCHEDULED`（不会直接 PUBLISHED）。

### 7.2 列表操作（事件委托于 tbody）

| 操作 | 行为 | toast |
|---|---|---|
| 点击发布编号 / `查看` | `openEdit(row,'view')` | — |
| `编辑` | `openEdit(row,'edit')` | — |
| `基于此版本新建` | `openEdit(row,'copy')` | `已复制 {version} 的全部内容为新草稿` |
| `发布` | **不校验、不确认**，直接 `status='SCHEDULED'`，刷新列表并回列表 | `已提交发布，{eff 或 2026-10-15 00:00} 生效` |
| `取消发布` | 记 cancelId，清空原因，打开取消发布弹窗 | 见 6.6.1 |
| `删除` | 记 delId，写入确认文案，打开删除确认 | 见 6.6.2 |
| 点击同意人数 | 不跳转 | `跳转「隐私授权记录」，按版本号 {version} 筛选` |

### 7.3 编辑视图「提交发布」校验（按顺序，命中即停）

1. **版本号必填**：依次检查 `隐私政策`、`用户服务协议` 两个 Tab 当前激活语言面板中的版本号（trim）。为空 → 切到该主 Tab，错误 toast `「隐私政策」版本号不能为空` / `「用户服务协议」版本号不能为空`。
2. **全部 4 种语言必须填全**，按 隐私政策 → 用户服务协议 → 变更内容弹窗 顺序检查：
   - 隐私政策 / 用户服务协议：文档标题 trim 非空 且 正文去掉 HTML 标签后 trim 非空；
   - 变更内容弹窗：弹窗标题 trim 非空 且 弹窗正文 trim 非空。
   - 有缺失 → 切到该主 Tab、语言子 Tab 切到第一个缺失语言，错误 toast `「{隐私政策|用户服务协议|变更内容弹窗}」还有未填全的语言：{缺失语言 label 用、连接}`，例：`「隐私政策」还有未填全的语言：Bahasa Indonesia、繁體中文`。
   - 默认数据中隐私政策/用户服务协议的 id-ID、zh-TW 正文以及弹窗的 id-ID、zh-TW 正文为空，因此不补内容直接提交必定在第 2 步被拦截。
3. **弹窗占位符校验**：对每种语言的弹窗正文，去掉所有 `{{客服电话}}` 后若仍有 `{{…}}` → 语言切到该语言、主 Tab 切到弹窗，错误 toast `弹窗正文存在未替换的占位符（{语言 label}）`（多个语言命中时取最后一个）。
4. 通过：`row.langs = ['zh-CN','en-US','id-ID','zh-TW']`，`row.has = ['P','S','C']`，`row.status='SCHEDULED'`，刷新列表、回列表，toast `已提交发布，{row.eff 或 2026-10-15 00:00} 生效`。
   - 表单中的发布编号、站点、生效方式、日期均**不写回行数据**。
   - copy 模式下 curRow 是源行，因此会把**源（已发布/已失效）行**改为待生效——实现缺陷，重写时应新建草稿行。

不校验：发布编号、站点、客服电话、生效时间、字数上限、版本号唯一性。

### 7.4 保存草稿

只 toast `已保存草稿`，不校验、不改数据、不离开编辑视图。

### 7.5 返回列表

直接切回列表，无未保存提示。

### 7.6 新建版本

1. 计算新版本号：遍历 ROWS，`parseFloat(version.replace('V',''))` 取最大值 +0.1，格式 `V{x.x}`。由于现有编号是 `VS2026…`，parse 结果为 NaN，最大值保持 0 → 新编号恒为 **`V0.1`**（实现缺陷；方案意图为自动 +0.1）。
2. 新行 `{ id: 100 + ROWS.length, version: nv, sites: ['新加坡'], langs: [], has: ['P','S','C'], status: 'DRAFT', eff: '', exp: '', total: 0, agree: 0, publisher: '刘伏旺', created: '2026-09-30 10:00' }`，**立即插到列表最前**（未保存也已出现在列表中）。
3. 预置日志 `[['2026-09-30 10:00','刘伏旺','创建草稿','新建']]`。
4. 清空除 zh-CN 外所有语言的隐私/服务协议正文和弹窗正文（文档标题、弹窗标题保留，zh-CN 内容保留作为默认模板），重算字数。
5. 打开 `new` 模式：标题 `新建协议版本 · V0.1`，状态标签「草稿」，日志卡片隐藏，版本号全部被设为 `V0.1`。

### 7.7 查询 / 重置

- `查询`：仅重新渲染全部数据（**不按条件过滤**），toast `查询完成`。
- `重置`：清空发布编号、发布人文本框（以及日期区间的隐藏 range-input），下拉 hidden 值置空、显示值置 `全部`，重新渲染，toast `已重置`。注意：日期区间可见的开始/结束输入框**不会被清空**（实现缺陷）。另外重置会把列表视图内所有带 `data-options` 的下拉都置为 `全部`，分页的「每页行数」也会被误显示成 `全部`（实现缺陷，重写时重置应只作用于查询表单）。

### 7.8 同意人数联动

方案：点击跳转「隐私授权记录」并带协议场景、版本号筛选。原型：仅 toast `跳转「隐私授权记录」，按版本号 {version} 筛选`。重写时应路由到隐私授权记录页并带 `version` 查询参数。

### 7.9 按钮显示 / 禁用汇总

| 元素 | 条件 |
|---|---|
| 页头「新建版本」 | 列表视图显示，编辑视图隐藏 |
| 编辑/发布/删除 | 仅 DRAFT 行 |

## 9. 其他细节

- 编辑视图的正文/标题/弹窗内容是**全行共享的一份 DOM**：打开任何行都显示同一份默认内容（只有发布编号、版本号、站点、生效时间框会按行回填）。重写时应按 `releaseId` 拉取详情，每个语言 × 3 类文档各自保存 `title / version / body`，弹窗另存 `phone`。
- 字数统计口径：去除所有空白字符后的字符数（含标点）。
- 正文 placeholder 为语言化文案（见附录 A）。
- `created` 字段存在于数据但不展示。
- 打开编辑视图不会滚动到顶部。
- 全局 Esc 关闭所有弹窗。
- 数据为内存 mock，刷新即复原。
- 建议数据模型（来自实现推断）：`{ id, version(发布编号), sites[], effType: 'IMMEDIATE'|'SCHEDULED', eff, exp, status, total, agree, publisher, created, langs[], has[], docs: { privacy|service: { [lang]: { title, version, body(html) } }, popup: { phone, [lang]: { title, body(text) } } }, logs: [{time, operator, action, remark}] }`。
