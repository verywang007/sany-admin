## 2. 查询区

使用 Table 内置的查询栏，表单是 3 列（`colgroup` 每列标签宽 0.8rem = 80px），标签右对齐，标签后带冒号（`useColon`）。默认显示前 3 个查询字段，其余字段通过“更多”按钮展开。

DataSet `queryFields`（按顺序）：

| # | 字段名 | 标签 | 控件 | placeholder | 选项 | 默认值 | 默认是否可见 |
|---|---|---|---|---|---|---|---|
| 1 | `problemType` | 错误类型 | 下拉单选（可清空，不可输入） | 请选择错误类型 | 远程获取：`GET /aftersale/v1/device-claim/select/type`，`dataKey: "data"`，显示字段 `typeName`，取值字段 `typeCode`，`autoQuery: true` | 空 | 是 |
| 2 | `replyState` | 状态 | 下拉单选（可清空） | 请选择回复状态 | `未回复`=0，`已回复`=1 | 空 | 是 |
| 3 | `feedback` | 反馈结果 | 下拉单选（可清空） | 请选择用户反馈结果 | `未解决`=0，`已解决`=1 | 空 | 是 |
| 4 | `times` | 起止日期 | 日期范围（`type: date`，`range: ["start","end"]`） | （c7n 默认：开始日期 ~ 结束日期） | — | 空 | 否（“更多”中） |
| 5 | `paramKey` | 设备编码 | 文本输入框 | 请输入设备编码或名称 | — | 空 | 否（“更多”中） |
| 6 | `createdByName` | 登录账号 | 文本输入框 | 登录账号 | — | 空 | 否（“更多”中） |

查询栏右侧按钮（顺序依次为）：
- **更多**（默认样式，后面带 `expand_more` 图标）：展开/收起其余查询字段（c7n professionalBar 默认行为：展开后显示“收起”和 `expand_less` 图标）。
- **重置**（默认样式）：清空查询条件。
- **查询**（primary 主色）：按条件查询。

查询参数：`GET /aftersale/v1/device-claim/select/param`，参数为查询字段值 + 分页，其中 `page` 发送时 **+1**（后端页码从 1 开始）。返回数据 `dataKey: data.content`，总数 `totalKey: data.totalElements`。DataSet `autoQuery: true`（进入页面自动查询一次），`primaryKey: id`。

## 3. 工具栏按钮

Table `buttons`（位于查询栏下方的 professional toolbar 内）：
- **导出**：c7n Button，快照里渲染为 `flat` + `primary`（文字型主色按钮，无图标）。
  - 行为：取查询 DataSet 当前值 `queryDataSet.toData()[0]`，与 `{ size: 当前每页条数, page: 当前页码 }` 合并成对象，`JSON.stringify` 后放在 `deviceClaimQuery` 字段里：`POST /aftersale/v1/device-claim/export/param`，body 为 `{ deviceClaimQuery: "<JSON 字符串>" }`，`responseType: blob`。
  - 成功后用 `<a download>` 下载，文件名 **`异常申诉清单.xls`**。失败只打 console.error，没有提示。

没有新建、批量操作等按钮。表格 `selectionMode: "none"`（无勾选列，无行号列）。

| 2 | `deviceName` | 设备名称 | 140 | 左 | 否 | 纯文本 |
| 3 | `creationDate` | 提交时间 | 140 | 左 | 否 | `dateTime` 类型（YYYY-MM-DD HH:mm:ss） |
| 4 | `createdByName` | 登录账号 | 默认（100） | 左 | 否 | 纯文本 |
| 5 | `problemTypeName` | 错误类型 | 默认（100） | 左 | 否 | 纯文本 |
| 6 | `devicePosition` | 设备经纬度 | 200 | 左 | 否 | 单行省略：`div` 设 `overflow:hidden; white-space:nowrap; text-overflow:ellipsis`（源码写的 `width:"180"`，没有单位，实际无效），外层包 Tooltip，`title` 为完整值；空值显示空字符串 |

DataSet 中另外定义但不作为列显示的字段：`id`（unique）、`index`（序号，type number，render 返回 `record.index`）、`replyState`（是否回复，string，用于判断操作按钮）。

### 操作列规则（`renderCommandButtons`）

按钮都是 c7n Button，套用样式 `AppealList_bandbtn`：`float:left; margin-top:2%; color:#29bece; border:none!important`（青色无边框文字按钮，左浮动排列）。

- 当 `record.replyState === "已回复"`（判断用的是中文文案字符串）时：
  - 如果 `record.feedback !== "已解决"`：显示 **回复**
  - 一律显示 **查看记录**
- 否则（未回复）：只显示 **回复**

即：
| replyState | feedback | 显示的按钮 |
|---|---|---|
| 已回复 | 已解决 | 查看记录 |
| 已回复 | 不是“已解决”（未解决/空） | 回复、查看记录 |
| 其他（未回复） | 任意 | 回复 |

## 6. 弹窗 / 预览

### 6.1 回复弹窗（点击“回复”）
- 打开方式：c7n `Modal.open`
- 标题：**回复内容**
- 宽度：500
- 按钮：c7n Modal 默认的“确定”和“取消”。点“确定”调用 `replayComplete()`。
- 打开时先把内部的 `replyData.problemReply` 和 `replyData.problemReplyImage` 清空。
- 内容（外层包 Form，组件容器 `width:100%; margin-bottom:-20px`）：
  1. **多行文本框**（TextArea，`$.a`）
     - placeholder：`请输入回复内容`
     - `maxLength: 300`，宽 100%
     - 没有标签，不标必填（必填由点击确定时的逻辑校验）
     - 下方右对齐的字数计数，颜色 `#7b7b7b`：`已输入{n}/300`，n 在 onInput 时按 `value.length` 更新
  2. **上传照片区**
     - 标题行（`margin-bottom:4px`）：`上传照片` + 灰色（`#7b7b7b`）文字 `（最多3张）`
     - 上传组件（基于 HZERO Upload 封装）：
       - extra 提示：`只能上传jpg/png格式文件，文件不能超过200M`
       - name：`problemImage`；directory：`/aftersale/images/case`
       - action：`${API_HOST}/aftersale/v1/device-claim/upload`
       - accept：`image/png`、`image/jpeg`；`multiple: true`；`fileListMaxLength: 3`；`sizelimit: 209715200`（200MB）
       - 请求头：`Authorization: bearer <token>`、`Access-Control-Allow-Origin: *`；附带 data `{ tenantId, bucketName: "s3", directory }`
       - beforeUpload 校验：
         - 文件大于 200MB → notification.error `文件超出大小限制，无法上传`，阻止上传
         - 文件名里不含 `.png`、`.jpg`、`.jpeg` → notification.error `请上传png或jpg图片`，阻止上传
       - 上传成功：解析响应 JSON，`failed` 为真则忽略；否则把 `data.originalUrl` 追加到 uploadImages，把 `data.url` 追加到预览列表；回调里把 uploadImages 用 `,` 拼成字符串写入 `replyData.problemReplyImage`
       - 删除文件：按 url 从两个列表中移除，再更新 `problemReplyImage`
       - 已上传列表显示为 `{name: url 最后一段去掉 query, type: "image/jpg", status: "success", uid, url}`
- 点“确定”的逻辑：
  1. `replyData.id = ds.current.get("id")`（注意：取的是 DataSet 的当前行。点击操作按钮时行会成为 current）
  2. `problemReply` 为空 → message.info `回复内容不能为空`，返回 false，弹窗**不关闭**
  3. `POST /aftersale/v1/device-claim/reply`，body `{ problemReply, problemReplyImage, id }`
  4. 不论成功失败都重新查询列表 `ds.query()`；`failed` 为真 → message.info(后端 message)，否则 message.success `操作成功`；弹窗关闭

## 7. 交互逻辑汇总

1. 进入页面自动查询（autoQuery），错误类型下拉的选项也自动拉取。
2. 查询：查询栏“查询”按钮 → 用查询条件请求 `/select/param`，page 参数 +1。
3. 重置：清空查询条件（c7n 默认行为）。
4. 更多：展开/收起 起止日期、设备编码、登录账号 三个字段。
5. 操作按钮的显示规则见第 4 节，判断依据是 `replyState`（"已回复"）和 `feedback`（"已解决"）这两个中文文案。
6. 回复：必须填写回复内容，否则提示“回复内容不能为空”，弹窗不关闭；图片可选，最多 3 张，限 jpg/png、≤200MB；提交后刷新列表，提示“操作成功”或后端 message。
7. 查看记录：只读子表弹窗。
8. 导出：带当前查询条件和分页导出，下载 `异常申诉清单.xls`。
9. 缩略图点击 → 全屏遮罩大图，右上角 × 关闭。

提示控件区分：`u.a` 是 antd/c7n 的 `message`（顶部居中的轻提示，info/success）；上传校验用的 `ee.a` 是 `notification.error({ message })`（右上角通知框）。

## 9. 其他细节

- 页头不显示返回按钮。
- “状态”查询字段的 placeholder 是“请选择回复状态”，标签却是“状态”；“反馈结果”的 placeholder 是“请选择用户反馈结果”。
- 查询值和后端约定：`replyState`、`feedback` 查询时传 0/1；列表返回的 `replyState`、`feedback` 是中文文案（“已回复”“已解决”），操作列按中文判断。重写时要和后端确认，或按枚举映射处理。
- 导出接口用 POST，查询参数整体序列化成 JSON 字符串放在 `deviceClaimQuery`。
- 快照里查询下拉都是空值，没有展开态。
- 快照中 `c7n-pro-modal-container` 为空（没有打开的弹窗）。
