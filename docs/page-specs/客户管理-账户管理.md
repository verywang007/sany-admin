### 2.3 查询区按钮
三个按钮都用 `.customer_primaryColor` 样式：`width:200px; height:30px; background-color:#1e3255; border-color:#1e3255`（深海军蓝），hover 时 `background-color:#29bece; border-color:#29bece`（青色）；c7n raised + primary，白字。
- **展开**（图标 `expand_more`）↔ **收起**（图标 `expand_less`）：切换 `isShowMore`
- **查询**：`setTimeout` 里执行 `ds.query()`，500ms 后把 `isLoad` 设为 true（之后空表格的文案从“请添加筛选条件后查询数据”变成“暂无数据”）

### 2.4 控件变化如何传参
- 文本框：onChange 时更新 searchForm，并在 `setTimeout` 里调用 `ds.setQueryParameter(key, value)`
- 下拉、日期、树选择、开关：onChange 时立即调用 `ds.setQueryParameter`
- 修改字段不会自动查询，必须点“查询”（快捷日期除外，见 7.1）

## 6. 弹窗

### 6.1 认证用户 —— 第一步“编辑”
- `Modal.open`，标题 **编辑**，宽 500，按钮为 c7n 默认的确定/取消
- 打开前把 `state.customerCode` 清空
- 内容：Form 里一个文本框，label **客户编码/合同编码：**，`labelWidth` 130（非中文 180）；没有标必填，也没有 placeholder；onChange 写入 `state.customerCode`
- 点“确定”：
  - `customerCode` 为空 → 什么都不做，弹窗关闭（没有提示）
  - 否则 `GET /customer/v1/{org}/infos/query-info-crm?code={customerCode}&customerCountryCode={行的 countryCode}`
    - 失败 → message.error `获取用户编码失败:{message}`
    - 成功：从 `data` 取 `crmCustomerCategory`、`crmCustomerNo`，组装 `{ role: "NORMAL", authType: crmCustomerCategory, crmCustomerNo, infoId: 行 id }`
      - `authType === 2`（企业）→ 打开“角色选择”弹窗（6.2）
      - 否则直接认证：`authType === 1`（个人）→ `GET /customer/v1/{org}/auth/personal-auth`（query 为上面的对象）；其他 → `POST /customer/v1/{org}/auth/enterprise-auth`（同样放 query）
      - 认证成功 → message.success `认证成功`，按当前页重查；失败 → message.error `认证失败:{message || "请联系管理员"}`
- 认证类型常量：`UN_AUTH: 0, PERSIONAL_AUTH: 1, ENTERPRISE_AUTH: 2, AGENT_AUTH: 3`

### 6.2 角色选择
- `Modal.open`，标题 **角色选择**，默认确定/取消
- 内容：Form 里两个单选 Radio（name `role`）：**非管理员**（value `NORMAL`）、**管理员**（value `ADMIN`）。源码没有设置默认选中项，state.role 初始为 `"NORMAL"`（state 跨次打开不重置）
- 确定：`role = state.role`，调用企业认证 `POST /auth/enterprise-auth`；成功 message.success `认证成功` 并重查；失败 message.error `认证失败:{message || "请联系管理员"}`

### 6.3 取消认证
- `crmBindList` 有值：
  - `Modal.open`，标题 **取消认证**
  - 内容：对每个非空绑定项显示一行（`display:flex; justify-content:space-between`），一个 Radio（name `base`，value 为该项 `id`，文字为该项 `crmCustomerNo`），各行同名，所以只能单选
  - 自定义底部按钮：**取消**（关闭）、**确认**（`color: blue`）
  - 确认：如果没选 → message.error `请选择需要取消认证的客户代码`；选了 → 关闭弹窗 → 再弹 `Modal.confirm` 标题 **您确定要解绑该用户吗？** → 确定后 `DELETE /customer/v1/{org}/crms`，body `{ customerInfoId: 行 id, customerInfoCrmId: 选中的绑定 id }` → 成功 message.success `操作成功` 并重查当前页；失败 message.error（后端 message，没有就用 `操作失败`）
  - 注意：源码判断是否已选用的是 `a && a.length`，Radio 的值是绑定 id；如果 id 是数字，`.length` 为 undefined，会一直提示“请选择…”。重写时按“是否有选中值”判断即可
- `crmBindList` 为空：`Modal.open` 标题 **取消认证**，内容为空，底部只有 **关闭** 按钮

### 6.4 重置密码
- 先弹 `Modal.confirm`：标题 **确定重置密码吗？**
- 确定后打开 `Modal.open`：标题 **重置密码**，宽 500，默认确定/取消
- 表单（独立 DataSet，autoCreate，初始数据 `{ loginName: 行 loginName, newPwd: 随机密码 }`）：
  | 标签 | 字段 | 控件 | 必填 | 规则 / 提示 |
  |---|---|---|---|---|
  | 登录名 | `loginName` | 文本框，只读 | 否 | — |
  | 新密码 | `newPwd` | 文本框，后缀是 `refresh` 图标，点击重新生成随机密码 | 是 | 正则 `/^(?!^\d+$)(?!^[A-Za-z]+$)(?!^[~!@#$%^&*_.]+$).{8,16}$/`；help 文案 `密码8到16位，并至少包含下面两种：字母（不区分大小写）、数字、特殊字符~!@#$%^&*_.` |
- 随机密码生成 `pe(8, "medium")`：长度 8；先各取 1 个小写字母、大写字母、数字，剩下 5 位从“小写 + 大写 + 数字”中随机取（high 级别还会包含特殊字符 `! @ - _ = < > # * % + & ^ $`，low 级别只有小写 + 数字，本页用 medium）
- 确定：校验不通过则返回 false（弹窗不关）；通过后 `PUT /customer/v1/{org}/infos/{userId}/password-reset`，body `{ password: 新密码, organizationId }` → 成功 message.success `操作成功` 并重查当前页；`failed` → message.error `操作失败`

### 6.5 修改邮箱（点击邮箱单元格）
- `Modal.open`，标题 **修改邮箱**，宽 500
- 表单：**邮箱**（`email`，必填，初始为行 email；正则 `/^[A-Za-z0-9._%+-]+@[A-Za-z0-9.-]+\.[A-Za-z]{2,}$/`；help `请输入正确的邮箱格式`）
- 确定：为空 → message.error `邮箱不可为空`，返回 false；校验不通过 → false；`POST /customer/v1/{org}/customer-info/update-email?userId=&email=` → 成功 message.success `操作成功` 并重查；失败 message.error(后端 message || `操作失败`)

### 6.6 修改联系电话（点击联系电话单元格）
- 先加载 `GET /customer/v1/{org}/citys/page`（pageSize 999），只保留有 `internationalCallPrefix` 的国家
- `Modal.open`，标题 **修改联系电话**，宽 500
- 表单（初始 `{ internationalCallPrefix: 行的值, phone: 行 contactPhone }`）：
  - **区号**（`internationalCallPrefix`，下拉，可搜索，placeholder `请选择区号`，选项文字 `{cityName}({internationalCallPrefix})`，value 为 internationalCallPrefix）
  - **联系电话**（`phone`，文本框，必填）
- 确定：phone 为空 → message.error `联系电话不可为空`，返回 false；校验 → `POST /customer/v1/{org}/customer-info/update-phone?userId=&phone=&internationalCallPrefix=` → 成功 `操作成功` 并重查；失败 message.error(后端 message || `操作失败`)

### 6.7 修改国家（代码存在，但菜单没有入口）
- `Modal.open`，标题 **修改国家**，宽 500；Form 里一个下拉 **国家**（必填、可搜索，name `countryCodes`，选项来自 `/citys/auth-page` 的 `cityName`/`cityCode`，初始为行 countryCode）
- 确定：校验 → `POST /customer/v1/{org}/infos/country`，body `{ userId, countryCode }` → `操作成功` / `操作失败`；取消时清空临时状态
- 是否在重写中保留入口需要和产品确认

## 7. 交互逻辑（完整规则）

### 7.1 认证日期快捷选项（页头 今日/昨日/本周/本月）
- 选项 value：今日=1、昨日=2、本周=3、本月=4
- 点击后为 `time2`（认证日期）设置范围，写入 searchForm，`searchForm2.time2 = value`（高亮），`ds.setQueryParameter("time2", 范围)`，并**立即查询** `ds.query()`
  - 今日：今天 00:00:00 → 当前时刻
  - 昨日：昨天 00:00:00.000 → 昨天 23:59:59.999
  - 本周：本周一 00:00:00（周日算作本周最后一天）→ 当前时刻
  - 本月：本月 1 日 00:00 → 当前时刻
  - 发送时还会再转换成 `startAuthDate = YYYY-MM-DD 00:00:00`、`endAuthDate = YYYY-MM-DD 23:59:59`
- 高亮条件：`searchForm2.time2 === 该选项 value`。只有“重置”会清除高亮；手动改认证日期不会清除高亮
- 快捷选项触发的查询不会把 `isLoad` 设为 true（空文案仍是“请添加筛选条件后查询数据”）

### 7.2 批量导入
- 点“批量导入” → 触发隐藏 file input（只接受 `.xlsx,.xls`）
- 选中文件后：`POST /customer/v1/{org}/crms/batch-regist-excel`（FormData `file`，`responseType: blob`），选完把 input 的 value 清空，以便重复选择同一文件
- 响应：`failed` → notification.error `{ description: 后端 message }`；否则把返回的 blob 下载为 `账号管理导入_{n}.xlsx`（导入结果文件），然后 `ds.query()`；下载出错 → notification.error `{ description: "账号管理导入_{n}下载失败" }`
- `n` 的生成：`年 + (月+1) + 日 + 时 + 分` 是**数字相加**（例如 2026+10+9+8+30=2083），不是拼接。重写时建议改成 `YYYYMMDDHHmm`

### 7.3 批量解绑
- 没有勾选任何行 → 什么都不发生（没有提示）
- 有勾选 → `Modal.confirm`：标题 **您确定要解绑以下【{N}】个用户吗？**，内容为每个选中用户的 `loginName`（每个一个块）
- 确定 → `POST /customer/v1/{org}/infos/batch-delete/user`，body `{ ids: [选中行 id] }`
  - 成功 → `notification.open({ message: "消息提示", description: "解绑成功" })`，按当前页重查
  - 失败 → `notification.error({ message: "消息提示", description: "解绑失败,请联系管理员" })`

### 7.4 导出
- `state.showExport` 默认为 false，所以显示的是自定义“导出”按钮（另一个分支是 HZERO ExcelExport：`requestUrl /customer/v1/{org}/infos/export`，文件名 `客户管理列表_YYYYMMDD`，白字 `#29bece` 底，但不会被渲染）
- 点击：`GET /customer/v1/{org}/infos/export-all-to-zip-batch`，query 为 `getQueryParameter()`（即 searchForm 经过 2.2 的转换，并删掉 undefined/null/"" 的键；**不包含表格排序和分页**），`responseType: blob`
- 下载文件名：`客户管理列表_YYYYMMDD.zip`
- 出错只打 console，没有提示
- 源码里另有 `showExportTips`：关闭 key 为 `exportTip` 的通知并 message.error `最多导出1万条数据，请重新选择筛选条件`，但没有被调用

### 7.5 锁定 / 解锁
- `Modal.confirm` 标题：解锁 → **确定解锁用户吗？**；锁定 → **确定锁定用户吗？**
- 确定：解锁 `GET /customer/v1/{org}/infos/users/unlocked?userId=`；锁定 `GET /customer/v1/{org}/infos/users/locked?userId=`
- `failed` → message.error `操作失败`；否则 message.success `操作成功`，按当前页重查

### 7.6 演示模式
- 菜单项由 `demoStatus` 决定：0 → 开启演示模式（紫）；其他 → 关闭演示模式（红）
- `Modal.confirm` 标题：**确定开启演示模式吗？** / **确定关闭演示模式吗？**
- 开启：先**不等待结果**地调用 `POST /aftersale/v1/device-users-auditor/demo/save`，body `{ deviceNo: "TC2050CB9073", userId, tenantId: 当前组织, userName: alias, type: 1 }`（写死的演示设备号）；再调用 `POST /customer/v1/{org}/infos/users/demo-status` body `{ userId, demoStatus: 1 }`
- 关闭：`POST .../infos/users/demo-status` body `{ userId, demoStatus: 0 }`
- 结果：`failed` → message.error `操作失败`；否则 message.success `操作成功` 并重查当前页
- 开启后“角色”列显示为 `{角色}·演示用户`

### 7.7 认证 / 取消认证
见 6.1 至 6.3。按钮显示规则：
| authStatus | crmBindList | 操作列前两个按钮 |
|---|---|---|
| 1（已认证） | 有值 | 取消认证、认证用户 |
| 1 | 空 | 取消认证 |
| 非 1 | 任意 | 认证用户 |

### 7.8 设备绑定审核
跳转到路由 `/auth/{realName}/{loginName}/{contactPhone}/{userId}/{tenantId}`（同一应用内的另一个页面）。

### 7.9 单元格内的下拉修改（角色 / 身份 / 印尼试点用户）
- 点击单元格（`trigger: click`）弹出菜单，点菜单项立即提交，**没有确认框**：
  - 角色：`POST /customer/v1/{org}/customer-info/update-role?userId=&role={key}`
  - 身份：`POST /customer/v1/{org}/infos/identity`，body `{ userId, identity: key }`
  - 印尼试点用户：`POST /customer/v1/{org}/infos/users/label`，body `{ userId, label: key }`
- 结果：`failed` → message.error `操作失败`；否则 message.success `操作成功` 并重查当前页

### 7.10 初始化（componentDidMount）
- 加载国家树 `/citys/auth-tree`（查询区“国家”）
- 加载国家列表 `/citys/auth-page`（修改国家用）
- 加载值集：`CUSTOMER.TELNET.AUTH_TYPE_CODE`（认证类型）、`CUSTOMER.TELNET.AUTH_STATUS_CODE`（认证状态）、`CUSTOMER.INFO.ROLE`（角色字典与菜单）、`CUSTOME_IDENTITY`（身份字典与菜单）
- 不自动查询列表

### 7.11 提示控件
- `message`（顶部居中轻提示）：操作成功/操作失败、认证成功/失败、各种校验提示
- `notification`（右上角通知）：批量解绑结果（标题“消息提示”）、导入失败/下载失败
