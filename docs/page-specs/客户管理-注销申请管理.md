# 客户管理-注销申请管理 页面规格

> 来源：`客户管理-注销申请管理.html`。这是**手写 HTML + CSS + 原生 JS** 原型，不是 HZERO 快照。有两段样式：基础 `<style>`，以及覆盖层 `<style id="account-management-alignment">`（注释说明用途是“与「账户管理」保持同一套 HZERO 页面壳、密度和主色”，**以覆盖层为准**）。页面逻辑在一个无 id 的 `<script>` IIFE 中，下文完整提取。
> 业务背景见同目录 `客户管理-账户注销-方案.md`（§3 状态机、§7.2 列表、§7.3 详情、§7.4 审核弹窗）。
> 复杂度：**高**。包含状态机驱动的操作列、详情弹窗（4 个 Tab）、确认弹窗（带必填校验）、toast、前端筛选和分页、CSV 导出，还会通过 localStorage 和 App 端原型同步数据，并按用户类型自动审核。

### 分页

- 底部分页条（高 52px，右对齐，12px，颜色 `#7e8ca2`）：「每页行数：」+ select（20 / 50 / 100，默认 20）+ `#pageInfo` + 首页 « / 上一页 ‹ / 下一页 › / 尾页 »（27×25px 按钮，aria-label 分别为「首页」「上一页」「下一页」「尾页」）。
- 初始 HTML 中 pageInfo 为「1 - 7 / 49」，下一页和尾页可用。脚本渲染后变为 `{start+1} - {end} / {total}`，7 条时为「1 - 7 / 7」，四个翻页按钮都禁用。总数为 0 时显示「0 - 0 / 0」。
- 规则：`pages = max(1, ceil(total/pageSize))`；page 限制在 [1, pages]；page<=1 时禁用首页和上一页；page>=pages 时禁用下一页和尾页；切换每页条数后回到第 1 页。
- 说明：HTML 静态写的是 49 条，与 7 条数据不一致；脚本以真实数据为准。重写时以接口 total 为准。

## 7. 交互逻辑（完整规则）

### 7.1 状态流转（确认弹窗点「确认」）

1. `note = 文本域.trim()`。
2. 若 `actionType==='reject'` 且 note 为空：toast **「驳回原因不能为空」**，聚焦文本域，**终止**。
3. 根据操作改写当前行：
   - approve：PENDING → **COOLING**（冷静期）
   - reject：PENDING → **REJECTED**（已驳回）
   - retry：FAILED → **PROCESSING**（注销中）
   - revoke：COOLING → **REVOKED**（已撤销）
4. 若是原型行（`prototype:true`），调用 `persistPrototypeApply` 回写 localStorage：`status`、`updatedTime=now`；approve 时写 `auditTime`、`auditOpinion = note || '审核通过'`、`coolingEnd = now + 15 天`，并把行的 `cool` 更新为格式化后的时间；reject 时写 `auditTime`、`auditOpinion = note`；retry 时写 `processingTime`；revoke 时写 `revokeTime`。
5. 关闭确认弹窗**和**详情弹窗。
6. 按当前查询条件重新筛选（不弹查询 toast），回到第 1 页。
7. toast：原型行为「**操作成功，已同步至 App 注销状态**」，其他行为「**操作成功，已记录操作日志**」。
- 注意：非原型行 approve 时 `cool` 不会更新（保留原值，如 `—`）。重写时应设为 now + 15 天。

### 7.2 按钮显示规则汇总

- 行操作：见 §4 操作列表。
- 详情弹窗的「驳回」「审核通过」：仅 PENDING 时显示。
- 方案 §7.1 提到 PROCESSING 状态下所有操作置灰，原型中 PROCESSING 只显示「查看详情」，效果一致。

### 7.3 查询 / 重置 / 刷新 / 导出

- **查询**（按钮或在查询面板内按 Enter）：按 §2 规则组合过滤（AND），渲染并回到第 1 页，toast「**查询完成，共 {n} 条记录**」。
- **重置**：清空所有 input，所有 select 设为 ""，移除统计卡的 active 状态，显示全部 rows，回到第 1 页，toast「**筛选条件已重置**」。
- **刷新**：`syncPrototypeApply()` 重新读取 localStorage，按当前条件过滤（无查询 toast）。若读到的原型行 `autoApproved` 为真，toast「**已同步 App 申请：个体户免人工审核，系统自动审核通过并进入冷静期**」；否则 toast「**列表已刷新，已同步 App 申请**」。
- **跨页签同步**：监听 `window` 的 `storage` 事件，key 为 `mysany.cancelPrototype.v1` 时同步并重新过滤。toast 为「**收到新的 App 申请：个体户已自动审核通过，进入冷静期**」（autoApproved 时）或「**收到新的 App 注销状态**」。
- **导出**：将当前过滤结果 `currentList`（全部页，不只是当前页）生成 CSV，带 BOM `﻿`，`text/csv;charset=utf-8`，文件名 `注销申请列表.csv`；每个值用双引号包裹，内部的 `"` 转义为 `""`。
  - 表头：申请单号, 用户ID, 昵称, 联系电话, 用户类型, 国家/地区, 注销原因, 校验结果, 注销状态, 申请时间, 完成时间
  - 字段：no, id, user, phone, userType, country, reason, risk, statusText, apply, finish（没有冷静期截止）
  - toast「**已导出当前 {n} 条记录**」
