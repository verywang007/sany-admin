# 客户管理 · 隐私授权记录 产品需求文档（PRD）

> 路由：`#/customer/privacy-auth`　｜　页面规格：`docs/page-specs/客户管理-隐私授权记录.md`

---

## 一、背景与目标

### 1.1 背景

C 端用户在 APP / PC 端同意隐私协议、用户服务协议及各项系统权限（位置、相机等）时，会产生授权记录。监管检查、客诉或协议改版时，需要在后管快速查到「谁、何时、在哪个终端、在什么场景下、对哪个协议版本或权限」做过同意，并能出示授权来源（客户端版本、设备、IP 等），作为隐私合规的举证依据。

只有「谁、哪个版本、什么时间」的记录，举证时容易被质疑「不是本人操作」「用户看到的不是这个版本」「是默认勾选而非主动同意」。因此在授权记录中补充授权场景和授权来源信息。

&nbsp;

### 1.2 目标

1. 在 `客户管理 → 隐私授权记录` 提供授权记录的只读查询能力，支持按客户、终端、同意类型、授权场景、协议版本、时间组合筛选。
2. 每条记录可查看完整的授权来源（客户端版本、设备、IP、协议语言、协议正文哈希等），增强举证力。
3. 与「通用配置 → 隐私服务协议管理」打通：点击某版本的「同意人数」直接跳入本页，查看该版本的同意明细。
4. 支持按当前查询条件导出，用于线下归档或对外提交：监管检查、客诉举证时需要提供书面 / 文件形式的授权凭证，在线查询页面无法直接作为材料提交。

## 二、术语与概念

| 概念    | 说明                                              |
| ----- | ----------------------------------------------- |
| 授权记录  | 用户的一次同意行为，一行一条；同一客户对不同类型、不同版本的每次同意各占一行          |
| 同意类型  | 用户同意的对象：协议类（隐私协议、用户服务协议）或权限 / 个人信息使用类（位置、相机等），共 9 种 |
| 终端    | 产生授权的端：APP / PC                                 |
| 版本号   | 用户同意时的协议版本，对应「隐私服务协议管理」中的版本，如 `V2.1`             |
| 授权场景  | 用户在哪个环节、通过什么界面做出同意，如注册、协议改版重新同意，共 6 种（见 §6.3） |
| 授权来源  | 授权发生时的客户端版本、设备、操作系统、IP、语言等环境信息（见 §6.4）           |
| 先筛选后查询 | 进入页面不自动加载数据，需点击「查询」后才返回结果                       |

## 三、用户与场景

| 角色         | 场景                         | 使用功能          |
| ---------- | -------------------------- | ------------- |
| 合规 / 法务    | 监管检查、客诉举证，需证明某客户在某时同意过某协议   | 按客户 + 时间查询、导出 |
| 运营 / 产品    | 协议改版后，查看新版本的同意情况，以及老用户是否已重新同意 | 从协议管理跳入，按版本 + 授权场景查询 |
| 客服         | 客户咨询「我是否授权过某权限」             | 按手机号 / 客户ID 查询 |

核心用户故事：

1. 作为合规人员，我要输入客户手机号和时间段，查出该客户全部授权记录并导出，以便提交给监管或用于客诉答复。
2. 作为产品经理，我在协议管理里点击 V3.0 的同意人数，希望直接看到哪些客户、在哪个端、何时同意了 V3.0；再按「协议改版重新同意」筛选，确认老用户已重新取得同意。
3. 作为合规人员，面对「该授权不是本人操作」的质疑时，我要打开某条记录，出示当时的设备、IP 和服务端接收时间。

## 四、需求范围总览

```
客户管理 → 隐私授权记录
├── 查询区（8 个条件 / 查询 / 重置）
├── 结果提示条（条数 + 条件描述）
├── 授权记录列表（只读 / 分页 / 行内「详情」）
├── 详情抽屉（授权信息 + 授权来源，只读）
├── 导出（按当前条件，含全部来源字段）
└── 外部入口：隐私服务协议管理 → 同意人数 → 带 ?version= 跳入并自动查询
```

本页为只读页面：无新增、编辑、删除；只有一个只读的详情抽屉。

## 五、功能需求

### 5.1 入口

| 入口       | 路径                                                       | 进入后状态                         |
| -------- | -------------------------------------------------------- | ----------------------------- |
| 菜单       | 客户管理 → 隐私授权记录（位于「注销申请管理」与「客户分析」之间）                     | 不自动查询，表格显示「请添加筛选条件后查询数据」      |
| 隐私服务协议管理 | 列表点击「同意人数」→ `#/customer/privacy-auth?version=<版本号>` | 先重置查询区，再将版本号填入「版本号」并自动查询      |

页面以多页签打开，标题「隐私授权记录」；切换页签保留已查询的结果。

### 5.2 页面结构

自上而下：

1. **页头**：左侧标题「隐私授权记录」，右侧「导出」按钮。
2. **查询区**：4 列栅格，8 个条件（两行各 4 个），下方「查询」「重置」按钮。
3. **结果提示条**：查询后显示；未查询时不显示。
4. **数据表格**：10 列（含末尾操作列），带边框，无勾选列。
5. **分页条**：常驻显示。

### 5.3 查询条件

全部可空，多个条件之间为「且」关系。

| 序号 | 标签   | 控件                          | 占位 / 选项           | 默认值 | 匹配规则                        |
| -- | ---- | --------------------------- | ----------------- | --- | --------------------------- |
| 1  | 客户ID | 文本框                         | 请输入客户ID           | 空   | 模糊包含，原样子串匹配                 |
| 2  | 客户昵称 | 文本框                         | 请输入客户昵称           | 空   | 模糊包含，忽略空格与大小写               |
| 3  | 手机号  | 文本框                         | 请输入手机号            | 空   | 模糊包含，忽略空格（可只输号码段，也可带区号）     |
| 4  | APP/PC | 下拉单选，可清除                   | 全部、APP、PC         | 全部  | 精确匹配；「全部」或清空 = 不限           |
| 5  | 同意类型 | 下拉单选，可清除                   | 全部 + 9 个类型（见 §6.1）；随 APP/PC 联动 | 全部  | 精确匹配；「全部」或清空 = 不限           |
| 6  | 授权场景 | 下拉单选，可清除                   | 全部 + 6 个场景（见 §6.3）；随 APP/PC 联动 | 全部  | 精确匹配；「全部」或清空 = 不限。来源采集上线前的记录无场景，选了具体场景时不会命中 |
| 7  | 版本号  | 文本框                         | 请输入版本号            | 空（从协议管理跳入时为带入的版本号） | 模糊包含，忽略空格与大小写               |
| 8  | 时间区间 | 日期范围（仅日期 `YYYY-MM-DD`，分隔符 ~） | 开始日期 / 结束日期       | 空   | 按同意时间的日期部分比较，含两端；可只填一端      |

- **终端与同意类型联动**：APP/PC 选「PC」时，同意类型下拉只保留「全部」「隐私协议」「用户服务协议」；若已选的是 APP 专属类型（位置、相机等），自动清空回「全部」。APP/PC 为「全部」或「APP」时显示全部 9 个类型。
- **终端与授权场景联动**：APP/PC 选「PC」时，授权场景下拉只保留「全部」「注册」「登录」「协议改版重新同意」；若已选的是 APP 专属场景（首次启动、设置页主动开启、功能入口单独授权），自动清空回「全部」。
- 同意类型与授权场景之间不做联动；组合不相容时（如「相机」+「首次启动」）查询结果为 0 条。
- 文本类条件提交前去掉首尾空格。
- 查询区内按 Enter 等同点击「查询」。
- 日期选择：第一次点击设起点，第二次设终点；终点早于起点时自动交换。

### 5.4 列表字段

按**同意时间倒序**，列宽可拖拽，单行显示、超长截断。

| 序号 | 列名   | 字段          | 宽度        | 格式与示例                                  |
| -- | ---- | ----------- | --------- | -------------------------------------- |
| 1  | 客户ID | customerId  | 120px     | 8 位数字，如 91667759                       |
| 2  | 客户昵称 | alias       | 120px     | 超长省略号，如 矿山设备管家                         |
| 3  | 手机号  | phone       | 140px     | `+区号 号码`，如 +86 13982033231              |
| 4  | APP/PC | terminal    | 100px     | APP / PC                               |
| 5  | 同意类型 | consentType | 130px     | 如 个性化推荐                                |
| 6  | 版本号  | version     | 100px     | 如 V2.1                                 |
| 7  | 授权场景 | scene       | 150px     | 场景文案，如 协议改版重新同意；无来源信息时显示 `—`       |
| 8  | 客户端版本 | clientVersion | 110px   | APP 为版本号，如 5.3.2；PC 为 Web 前端版本，如 Web 2.8.0；无来源信息时显示 `—` |
| 9  | 同意时间 | consentTime | 自适应，吸收余量  | `YYYY-MM-DD HH:mm:ss`，如 2026-10-02 21:25:17（客户端上报时间） |
| 10 | 操作   | —           | 70px      | 「详情」文字按钮，打开详情抽屉（§5.7）               |

其余来源字段（设备、IP 等）不放进列表，避免列表过宽；在详情抽屉和导出文件中查看。

### 5.5 操作

| 操作 | 位置      | 行为                                                                  |
| -- | ------- | ------------------------------------------------------------------- |
| 查询 | 查询区下方，主按钮 | 按当前条件查询；页码回到第 1 页；刷新提示条、表格和分页。不填任何条件也可查询，返回全部记录                   |
| 重置 | 查询区下方   | 清空文本框和日期，下拉恢复「全部」；页面回到未查询状态；**不触发查询**                               |
| 导出 | 页头右侧    | 未查询时提示「请先查询数据后再导出」；已查询时按当前条件导出全部结果（不仅当前页）。导出列 = 列表前 9 列 + §6.4 的全部来源字段；**IP 导出完整值**，不脱敏 |
| 详情 | 列表操作列   | 打开右侧详情抽屉，见 §5.7                                                    |
| 分页 | 表格下方    | 每页行数 10 / 20 / 50 / 100，默认 20；修改后回到第 1 页                            |

### 5.6 结果提示条

格式：`共查询到 N 条授权记录（条件：……）`，N 加粗。条件按下列顺序拼接，用「；」分隔，只列出已填的项：

1. 客户ID 含「xxx」
2. 昵称 含「xxx」
3. 手机号 含「xxx」
4. 终端 = APP / PC
5. 同意类型 = xxx
6. 授权场景 = xxx
7. 版本号 含「xxx」
8. 同意时间 {开始或「不限」} ~ {结束或「不限」}

未填任何条件时显示「（未设置筛选条件，返回全部记录）」。

### 5.7 详情抽屉

右侧抽屉，标题「授权记录详情」，宽 560px，只读，无底部按钮。分两块：

**授权信息**

| 字段 | 说明 |
| -- | -- |
| 客户ID、客户昵称、手机号、APP/PC、同意类型、版本号 | 同列表 |
| 协议语言 / 界面语言 | 协议类显示「协议语言」，权限类显示「界面语言」；取值见 §6.4 |
| 授权场景 | 场景文案 |
| 同意时间（客户端） | 客户端上报的时间 |
| 服务端接收时间 | 服务端收到授权请求的时间；客户端时间可被篡改，举证以此为准 |

**授权来源**

| 字段 | 展示规则 |
| -- | -- |
| 客户端版本 | 原值 |
| 设备型号 / 浏览器 | APP 显示「设备型号」，PC 显示「浏览器」 |
| 操作系统 | 原值 |
| IP 地址 | **脱敏**，只保留前两段，如 `113.87.*.*`；下方提示「IP 已脱敏，完整 IP 请通过导出获取。」 |
| IP 归属地 | 如 中国 广东 深圳 |
| 设备ID（哈希） | 显示前 16 位 + `…`，可一键复制完整值 |
| 协议正文哈希 | 同上；权限类授权没有协议正文，显示 `—` |

来源采集上线前的记录：「授权来源」块替换为提示「该记录产生于来源信息采集上线（{上线日期}）之前，无授权场景及来源信息。」，授权信息块中的场景、语言、服务端接收时间显示 `—`。

## 六、数据规则

### 6.1 同意类型

| 同意类型   | 分类     | 适用终端    |
| ------ | ------ | ------- |
| 隐私协议   | 协议     | APP、PC  |
| 用户服务协议 | 协议     | APP、PC  |
| 位置     | 系统权限   | APP     |
| 相机     | 系统权限   | APP     |
| 无线数据   | 系统权限   | APP     |
| 发送通知   | 系统权限   | APP     |
| 头像使用   | 个人信息使用 | APP     |
| 个性化推荐  | 个人信息使用 | APP     |
| 其他APP活动 | 个人信息使用 | APP     |

### 6.2 其他字段取值

- 终端：APP、PC。
- 版本号：对应「隐私服务协议管理」中的协议版本，原型样本为 V1.0、V1.2、V2.0、V2.1、V2.5、V3.0、V3.2。

### 6.3 授权场景

授权场景由客户端在上报授权时一并传入，后管只负责展示和筛选，无法自行判断。其中「首次启动」「功能入口单独授权」对应的权限已按 MySANY 实际授权入口确认；**其余场景需与 APP / PC 研发核对**（见 Q9）。

| 编码 | 场景 | 典型界面 | 适用终端 | 对应同意类型 |
| -- | -- | -- | -- | -- |
| `FIRST_LAUNCH` | 首次启动 | APP 首次打开时弹出隐私政策，同意后申请位置、发送通知、其他APP活动、无线数据权限 | APP | 协议类；位置、发送通知、其他APP活动、无线数据 |
| `REGISTER` | 注册 | 注册页勾选「我已阅读并同意《用户服务协议》《隐私政策》」 | APP、PC | 协议类 |
| `LOGIN` | 登录 | 登录页勾选协议（验证码登录、第三方登录等） | APP、PC | 协议类 |
| `VERSION_UPDATE` | 协议改版重新同意 | 协议发布新版本后，用户下次打开时弹窗要求重新确认 | APP、PC | 协议类（首版 V1.0 不会出现） |
| `SETTINGS` | 设置页主动开启 | 用户在隐私设置中主动打开开关 | APP | 个性化推荐 |
| `FEATURE_ENTRY` | 功能入口单独授权 | 首次使用拍照、扫码时申请相机权限；首次上传头像时询问是否允许使用 | APP | 相机、头像使用 |

场景对举证的作用：

1. **证明同意是用户主动做出的**：勾选、弹窗点击、设置页主动开启的证明力不同，默认勾选可能被认定无效。
2. **证明协议改版后重新取得了同意**：按「版本号 + 协议改版重新同意」即可回答监管的这一常见问题。
3. **证明先告知、后申请权限**：首次启动时先取得隐私政策同意，再申请位置、发送通知等权限；相机在使用对应功能时才申请，而不是一启动就要。

### 6.4 授权来源字段

| 字段 | 名称 | 存储 | 列表 | 详情 | 导出 | 说明 |
| -- | -- | -- | -- | -- | -- | -- |
| scene | 授权场景 | 编码 | ✅ | ✅ | ✅ | 见 §6.3 |
| clientVersion | 客户端版本 | 原值 | ✅ | ✅ | ✅ | 证明当时的客户端会展示该版本协议 |
| lang | 协议 / 界面语言 | 语言编码 | — | ✅ | ✅ | 与协议管理的语言版本一致：简体中文、English、Bahasa Indonesia、繁體中文 |
| device | 设备型号 / 浏览器 | 原值 | — | ✅ | ✅ | |
| os | 操作系统 | 原值 | — | ✅ | ✅ | |
| ip | IP 地址 | 原值 | — | 脱敏 | 全量 | IP 本身是个人信息 |
| ipRegion | IP 归属地 | 原值 | — | ✅ | ✅ | 由服务端根据 IP 解析 |
| deviceIdHash | 设备ID | **仅存 SHA-256** | — | ✅ | ✅ | 不存明文；用于核对「是否同一设备」 |
| serverTime | 服务端接收时间 | 原值 | — | ✅ | ✅ | 举证以此为准 |

- 来源字段属于新增埋点，**上线前的历史记录无法补录**，这些字段为空，页面显示 `—`；

### 6.5 保留期限

- 账号存续期间：授权记录全部保留。
- 账号注销或授权撤回后：再保留 **3 年**（对应《民法典》一般诉讼时效），到期后删除或匿名化。起算点取「注销时间」与「撤回时间」中较早的一个。
- 注销期间按《客户管理-账户注销-方案》匿名化昵称和手机号，`customerId` 保留原值，否则注销后的记录无法举证；IP、设备ID 哈希随记录一起保留到期限届满。
- 到期清理由后台定时任务执行，后管不提供手工删除入口。

> 注：《客户管理-账户注销-方案》§6.2 关联数据处理中「隐私授权记录：全量保留」需同步改为「保留至注销后 3 年」。无限期保留不符合最小必要原则。

### 6.6 业务规则

- 授权记录只增不改，后管不提供修改或删除入口。
- 用户每同意一次（含协议改版后重新同意）即新增一条，历史记录保留至 §6.5 的期限。

## 七、状态与边界

| 状态  | 触发          | 提示条            | 表格            | 分页                   |
| --- | ----------- | -------------- | ------------- | -------------------- |
| 未查询 | 刚进入页面、点击重置  | 不显示            | 请添加筛选条件后查询数据  | `1 - 0 / 0`，全部置灰     |
| 有结果 | 查询返回 ≥ 1 条  | 共查询到 N 条……     | 展示当前页数据       | 正常翻页                 |

- 查询中表格显示加载态。
