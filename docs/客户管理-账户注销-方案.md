# 客户管理 · 账户注销 产品方案

> 基线页面：`客户管理-账户管理.html`（页面标题「账号管理」）
> 关联页面：隐私授权记录、组织管理、设备管理员配置、客户认证使用（CRM客户列表）、异常申诉
> 平台：MySANY 管理平台（hzero / c7n-pro），多站点（当前示例为新加坡站点），多语言，海外国家/大区/国区维度
> 状态：已生成原型
> 原型页面：`客户管理-注销申请管理.html`

---

## 一、背景与目标

### 1.1 背景

现有「账号管理」页具备的账户干预手段只有三类：

| 现有能力 | 位置 | 作用范围 |
| --- | --- | --- |
| 批量导入 | 工具栏 | 批量建账/批量维护 |
| 批量解绑 | 工具栏（红色按钮） | 解除账号与 `crmBindList`（已绑定客户编码）的绑定关系 |
| 锁定 | 列 `lockStatusCode` | 冻结登录，数据全部保留，可逆 |

缺口是：**没有"账户消亡"这一终态**。解绑只断开客户关系，锁定只冻结登录，两者都不满足个人信息保护法规里"删除权 / 被遗忘权"的要求，也无法把一个长期不用的账号移出活跃口径。

海外站点（新加坡 PDPA、印尼 PDP、欧盟 GDPR、国内《个保法》）普遍要求：用户可自助发起注销，且平台须在约定时限内完成个人信息删除或匿名化。当前后管无对应受理、审核、执行与留痕能力。

### 1.2 目标

1. 建立「注销」这一独立于锁定/解绑的终态，及其完整状态机。
2. 支持两条发起链路：**App 用户自助发起** 与 **后管人工代客发起**。
3. 沉淀前置校验规则，避免带资产、带责任身份的账号被误注销。
4. 注销执行后个人信息按字段级策略匿名化/删除，同时保留业务连续性所需的最小审计留痕。
5. 全链路可追溯、可举证，满足监管问询与用户投诉的回溯要求。

### 1.3 非目标（本期不做）

- 租户/组织整体注销（企业主体销户）→ 见 §9 后续规划
- 注销后的账号"复活/恢复"（冷静期外不提供）
- 历史数据的物理删除（本期为逻辑匿名化）

## 二、概念边界

这四个概念必须在产品文案与培训材料中严格区分，否则一线会混用：

| 概念 | 触发方 | 登录 | 客户绑定 | 个人信息 | 可逆性 |
| --- | --- | --- | --- | --- | --- |
| **锁定** | 后管 | 禁止 | 保留 | 保留 | 可解锁 |
| **解绑** | 后管 | 允许 | 清除 | 保留 | 可重新绑定 |
| **注销** | 用户 / 后管 | 永久禁止 | 清除 | 匿名化 | 冷静期内可撤销，之后不可逆 |
| **删除** | —— | —— | —— | 物理删除 | 本期不提供 |

**关键规则：注销 = 解绑 + 锁定 + 匿名化 + 不可逆**，执行时自动串联前两步，不需要运营手工先解绑再注销。

## 三、注销状态机

```
                      ┌──────────────┐
                      │   正常 NORMAL │
                      └──────┬───────┘
                             │ 用户App发起 / 后管代客发起
                             ▼
                   ┌────────────────────┐
         驳回       │  待审核 PENDING     │
      ┌────────────┤  (含前置校验结果)    │
      │            └──────┬─────────────┘
      │                   │ 审核通过
      │                   ▼
      │         ┌────────────────────────┐
      │         │  冷静期 COOLING (T+15d) │◄── 期间任意登录即撤销
      │         └──────┬─────────────────┘
      │                │ 冷静期届满，定时任务触发
      │                ▼
      │         ┌────────────────────┐        ┌──────────────┐
      │         │  注销中 PROCESSING  ├───失败──►│ 注销失败 FAILED│
      │         └──────┬─────────────┘        └──────┬───────┘
      │                │ 全部子任务成功                │ 人工重试
      │                ▼                              │
      │         ┌────────────────────┐                │
      │         │  已注销 CANCELLED   │◄───────────────┘
      │         └────────────────────┘
      ▼
┌──────────────┐
│  已驳回 REJECTED│ → 回到 正常
└──────────────┘

撤销路径：PENDING / COOLING ──用户或后管撤销──► 已撤销 REVOKED → 回到 正常
```

> **按用户类型分流的审核规则**：个体户（无企业租户/代理商身份）的自助申请，前置校验通过后由系统**自动审核通过，跳过 `PENDING` 直接进入 `COOLING`**；含企业租户/代理商身份的账号涉及客户关系、子账户与代理权益，仍须人工审核（经过 `PENDING`）。代客链路不变，维持双人审核。

### 3.1 状态定义（建议入值集，编码 `MYSANY.ACCOUNT_CANCEL_STATUS`）

| 编码 | 名称 | 标签色 | 账号可登录 | 说明 |
| --- | --- | --- | --- | --- |
| `NORMAL` | 正常 | 默认 | 是 | 无注销流程，列表默认不展示该标签 |
| `PENDING` | 待审核 | 橙色 | 是 | 已提交申请，等待运营审核（个体户自助申请自动通过，不经过此状态） |
| `REJECTED` | 已驳回 | 红色 | 是 | 校验未过或人工驳回，须填驳回原因 |
| `COOLING` | 冷静期 | 蓝色 | 是（登录即撤销） | 默认 15 天，可按国家配置 |
| `PROCESSING` | 注销中 | 紫色 | 否 | 执行中，禁止任何人工干预 |
| `CANCELLED` | 已注销 | 灰色 | 否 | 终态 |
| `FAILED` | 注销失败 | 红色 | 否 | 有子任务失败，需人工重试 |
| `REVOKED` | 已撤销 | 默认 | 是 | 用户主动撤回，回到正常 |

> **冷静期时长**为待确认项，15 天是行业常见取值（见 §10 Q1）。

## 四、发起链路

### 4.1 链路 A：App 用户自助发起（主链路）

```
App「我的-设置-账户与安全-注销账户」
  → 展示注销须知（资产清空提示 + 匿名化说明 + 冷静期说明）
  → 勾选同意（同步写入隐私授权记录，consentType = 注销协议）
  → 短信/邮箱验证码二次验证（与注册登录方式一致）
  → 系统执行前置校验（§5）
      ├─ 硬拦截命中 → 直接失败，展示具体原因与解决路径（不进后管）
      ├─ 软提醒命中 → 二次确认弹窗，用户确认后继续
      └─ 全部通过 → 提交：个体户由系统自动审核通过，状态 = COOLING；含企业租户/代理商身份，状态 = PENDING（人工审核）
```

**用户侧可见**：App 内保留「注销进度」入口，展示当前状态、预计完成时间、撤销按钮。

### 4.2 链路 B：后管人工代客发起

适用场景：用户通过客服热线/服务召请电话（`serveRecruitmentPhone`）、邮件、线下渠道提出注销；或用户 App 版本过低（`appVersion` 低于支持版本）无自助入口。

```
账号管理列表 → 选中行 → 操作列「注销」
  → 弹出「代客注销申请」弹窗
  → 必填：注销原因、申请来源、用户凭证（工单号/录音编号/邮件截图）
  → 系统执行同一套前置校验
  → 提交后状态 = PENDING，并强制走双人审核（发起人 ≠ 审核人）
```

**代客注销必须留存用户授权凭证**，这是合规举证的核心材料，不可选填。

## 五、前置校验规则

校验在"用户点击注销"时同步执行，并在"执行注销前"再校验一次（防止冷静期内状态变化）。

### 5.1 硬拦截（阻断，不允许提交）

| # | 规则 | 判定依据 | 提示文案（用户侧） |
| --- | --- | --- | --- |
| H1 | 当前是设备管理员 | 在「设备管理员配置」中存在 `adminMysanyNo` = 本账号的记录 | 您是 N 台设备的管理员，请先移交管理员权限 |
| H2 | 当前是组织唯一主账号 | 「组织管理」中该组织仅此一个主账号 | 您是组织「XXX」的唯一管理员，请先移交或解散组织 |
| H3 | 存在进行中的异常申诉 | 「异常申诉」中有未回复（`problemReply` 为空）记录 | 您有 N 条申诉处理中，完结后可注销 |
| H4 | 存在未完结订单 | 积分商城订单、运营活动订单处于未完成/退款中 | 您有未完成订单，请先处理 |
| H5 | 账号处于锁定状态 | `lockStatusCode` = 已锁定 | 账号异常，请联系客服 |
| H6 | 已有进行中的注销流程 | 状态 ∈ {PENDING, COOLING, PROCESSING} | 您已提交注销申请，请勿重复提交 |

### 5.2 软提醒（二次确认后可继续）

| # | 规则 | 判定依据 | 提示文案 |
| --- | --- | --- | --- |
| S1 | 有未使用积分 | `points` > 0 | 您还有 N 积分，注销后将清零且不可恢复 |
| S2 | 有账户星星 | `starNum` > 0 | 您的 N 颗星星将清零 |
| S3 | 已完成实名/企业认证 | `authTypeCode` 非空 | 注销后认证信息将一并清除，重新注册需再次认证 |
| S4 | 已绑定客户编码 | `crmBindList` 非空 | 注销将解除与客户「XXX」的绑定 |
| S5 | 是印尼试点用户 | `label` = 印尼试点用户 | 您参与的试点活动权益将失效 |

### 5.3 校验结果的可视化

校验结果需在后管审核弹窗中**完整回显**（含硬拦截/软提醒各命中几条、分别是什么），审核人凭此判断，不需要自己再去几个页面翻查。这是本方案里对运营效率影响最大的一点。

## 六、执行方案：数据处理策略

### 6.1 字段级处理清单（基于账号管理现有列）

| 字段 | 中文名 | 处理方式 | 处理后取值 | 理由 |
| --- | --- | --- | --- | --- |
| `userId` | 用户ID | **保留** | 原值 | 主键，审计与关联必需 |
| `alias` | 昵称 | 匿名化 | `已注销用户_{userId后6位}` | 直接标识符 |
| `loginName` | 登录用户名 | 匿名化 | `deleted_{userId}` | 释放原用户名可被再次注册 |
| `contactPhone` | 联系电话 | **哈希后删除明文** | 保留 SHA256 值用于防刷注册 | 需支持"同号码短期内重复注册"风控 |
| `email` | 邮箱 | 同上 | 保留哈希 | 同上 |
| `serveRecruitmentPhone` | 服务召请电话 | 删除 | 空 | 个人联系方式 |
| `firstLoginMethod` | 登录类型 | 保留 | 原值 | 统计口径，非个人信息 |
| `country` / `regionName` / `nationalRegionName` | 国家/大区/国区 | 保留 | 原值 | 合规管辖地判定必需 |
| `role` / `identity` | 角色/身份 | 保留 | 原值 | 报表口径 |
| `crmCustomerNo` / `crmBindList` | 客户编码/已绑定 | 清空 | 空 | 等同执行解绑 |
| `crmCustomerClassification` | 客户类别 | 清空 | 空 | 随绑定关系一并清除 |
| `authTypeCode` / `authDate` | 认证类型/认证日期 | 删除 | 空 | 实名信息为敏感个人信息 |
| 实名证件号、姓名、人脸等 | （明细表） | **物理删除** | —— | 敏感个人信息，不做匿名化保留 |
| `starNum` / `points` | 星星数/积分 | 清零 | 0 | 资产终止 |
| `appVersion` | APP版本号 | 保留 | 原值 | 统计口径 |
| `creationDate` | 注册日期 | 保留 | 原值 | 留存率/活跃统计必需 |
| `lastLoginTime` / `lastActiveTime` | 最近登录/最新活跃 | 保留 | 原值 | 同上 |
| `label` | 印尼试点用户 | 保留 | 原值 | 试点分析口径 |
| `lockStatusCode` | 锁定 | 置为锁定 | 已锁定 | 阻断登录 |

### 6.2 关联数据处理

| 关联对象 | 处理方式 |
| --- | --- |
| 隐私授权记录 | **全量保留**，`alias`/`phone` 同步匿名化。授权记录本身是合规举证材料，不可删 |
| 异常申诉 | 保留，`createdByName`（登录账号）替换为匿名值，`problemImage` 中含人脸/车牌的图片按图片治理策略单独处理 |
| 圈子内容/评论 | 保留内容，作者展示为「已注销用户」；用户可在注销须知中选择「同时删除我发布的内容」 |
| 积分明细 | 保留流水（财务留痕），关联展示匿名化 |
| 设备绑定关系 | 解除（H1 已保证不是管理员，此处仅解除普通绑定） |
| 消息/推送 Token | 物理删除，立即停止推送 |
| 登录凭证 / 第三方 OAuth 绑定 | 物理删除，解除第三方授权 |

### 6.3 执行方式

注销执行为**异步任务编排**，每个子系统一个子任务，任一失败整单置为 `FAILED` 并保留已成功子任务的幂等标记，人工重试时只跑失败项。

建议子任务：`账号主体匿名化` → `认证信息删除` → `资产清零` → `绑定关系解除` → `凭证/Token清理` → `关联内容匿名化` → `搜索/缓存索引刷新`。

## 七、后管页面方案

### 7.1 改造点 A：账号管理（现有页）

在不改变现有页面骨架的前提下增量改造：

**筛选区**（现有：注册日期、最近登录日期、认证日期、国家 + 展开/查询/重置）
- 新增「注销状态」多选下拉，选项取 §3.1 值集
- 新增「注销申请日期」日期范围
- 默认值：注销状态 = 全部（含已注销），避免运营以为数据丢了

**列表区**
- 新增列「注销状态」（放在现有「锁定」列之后，保持状态类字段聚合）
- 新增列「注销申请时间」「注销完成时间」（默认隐藏，可通过列配置开启）
- 已注销行整行文字置灰，昵称前加「已注销」灰色标签

**操作列**（现宽度 3.5rem，需扩容）
- 新增「注销」按钮：仅 `NORMAL` / `REJECTED` / `REVOKED` 状态可见
- 新增「注销详情」按钮：非 `NORMAL` 状态可见
- `PROCESSING` 状态下，该行所有操作按钮置灰不可点

**工具栏**
- 「批量解绑」右侧不新增批量注销按钮。**注销不提供批量操作**——单条误操作可控，批量误操作不可逆，风险收益不匹配。

**导出**
- 现有导出增加注销状态、注销申请时间、注销完成时间三列

### 7.2 新增页面 B：注销申请管理

菜单位置：`客户管理 → 注销申请管理`（与「异常申诉」平级，同为工单型页面）

这是运营的主战场，账号管理页只承担"从用户视角查"的场景。

**筛选区**
申请单号、用户ID、昵称、登录用户名、联系电话、注销状态（多选）、申请来源（App自助/后管代客）、国家（树选择，复用账号管理的 `cityCode` 组件）、大区、申请时间范围、完成时间范围、当前处理人

**列表列**

| 列 | 说明 |
| --- | --- |
| 申请单号 | 可点击进详情 |
| 用户ID / 昵称 / 登录用户名 / 联系电话 | 用户标识 |
| 国家 / 大区 | 管辖地，决定适用法规 |
| 申请来源 | App自助 / 后管代客 |
| 注销原因 | 枚举 + 其他（文本） |
| 校验结果 | `硬拦截 N / 软提醒 M`，点击展开明细 |
| 注销状态 | 状态标签 |
| 申请时间 | 可排序 |
| 冷静期截止时间 | 距今不足 3 天标红 |
| 完成时间 | —— |
| 审核人 / 审核时间 / 审核意见 | —— |
| 操作 | 审核通过 / 驳回 / 强制撤销 / 重试 / 查看详情 |

**默认排序**：注销状态优先级（FAILED > PENDING > COOLING > 其他）→ 申请时间倒序。让需要人干预的单子自然浮到顶部。

**列表页顶部统计卡**：待审核 N 单、冷静期 N 单、失败待重试 N 单、本月已完成 N 单。

### 7.3 新增：注销详情抽屉/弹窗

分四个 Tab：

1. **申请信息**：单号、用户快照（注销前的完整字段快照，这点很关键——注销后原数据已匿名化，快照是唯一回溯依据）、申请来源、原因、凭证附件
2. **校验结果**：硬拦截/软提醒逐条列出，命中的显示具体数值与跳转链接（如"设备管理员：3 台"→ 跳设备管理员配置页并带过滤条件）
3. **执行进度**：各子任务的执行状态、耗时、失败原因、重试按钮
4. **操作日志**：全链路时间轴，含操作人、IP、时间、动作、备注

### 7.4 审核弹窗

- 通过：需勾选「已确认用户身份真实性」「已确认校验结果」两项才可提交
- 驳回：驳回原因必填（枚举 + 补充说明），驳回后用户 App 可见原因

## 八、权限、审计与合规

### 8.1 权限设计

| 角色 | 查看列表 | 查看详情 | 代客发起 | 审核 | 强制撤销 | 重试 | 导出 |
| --- | --- | --- | --- | --- | --- | --- | --- |
| 客服专员 | ✓ | ✓ | ✓ | ✗ | ✗ | ✗ | ✗ |
| 运营主管 | ✓ | ✓ | ✓ | ✓ | ✓ | ✗ | ✓ |
| 系统管理员 | ✓ | ✓ | ✗ | ✗ | ✓ | ✓ | ✓ |
| 合规/法务 | ✓ | ✓ | ✗ | ✗ | ✗ | ✗ | ✓ |

**强制约束**：发起人不可审核同一单（双人原则）。

### 8.2 数据权限

沿用平台既有的站点/国家数据隔离：新加坡站点的运营只能看到 `country` 属于其管辖范围的注销申请。跨国查看需单独授权。

### 8.3 审计留痕

- 所有状态流转写操作日志，字段：操作人、操作人组织、IP、时间、前状态、后状态、备注
- 日志**不可编辑、不可删除**，保留期不低于 3 年（各地法规最长要求）
- 导出行为单独记日志（含导出条数、筛选条件），导出文件延用现有水印机制（页面已有 `mask_mark` 用户名水印）

### 8.4 合规时限

| 地区 | 法规 | 完成时限要求 | 本方案 |
| --- | --- | --- | --- |
| 中国 | 个保法 | 无明确天数，"及时" | 15 天冷静期 + 3 日内执行 |
| 欧盟 | GDPR Art.17 | 无不当延迟，通常 30 日 | 满足 |
| 新加坡 | PDPA | 合理时间内 | 满足 |
| 印尼 | PDP Law | 3×24 小时内响应 | **冷静期需按国家缩短，见 §10 Q1** |

**冷静期时长必须支持按国家配置**，不能全局写死——这是多站点平台的硬性要求。

## 九、对现有统计口径的影响

注销会改变以下报表的分母，需同步评估（涉及「客户分析-月活跃用户」「客户分析-用户留存率」「数据管理-用户活跃报表」「流失用户分析」）：

| 报表 | 影响 | 建议口径 |
| --- | --- | --- |
| 月活跃用户 | 已注销用户历史活跃是否计入 | **计入**。历史事实不因注销而改变，否则历史月份 MAU 会随时间回退 |
| 用户留存率 | 注销用户在后续周期必然不活跃 | 计入分母，视为流失。可增加「剔除注销用户」的对比开关 |
| 流失用户分析 | 注销是最强流失信号 | 新增「注销」流失类型，并接入注销原因分布 |
| 用户角色分布 / 群体画像 | 快照类报表 | 剔除已注销用户 |
| 认证用户数量（客户认证使用页 `authUserNum`） | 注销会减少 | 实时扣减 |

**原则**：时间序列类报表保留历史事实，截面快照类报表剔除已注销。这个口径需要和数据团队书面确认。
